# Material 3 — design system adoption

Everything numeric here is lifted from
[`material-components/material-web`](https://github.com/material-components/material-web)
`tokens/versions/v0_192/`, not from memory or from a blog post. Where this document
gives a number, that number is in that repository. Where it does not, we did not
have a source and did not invent one.

Material Web is in **maintenance mode** — no new components — but it is still
Google's reference implementation of the M3 token set, and the same tokens ship with
Angular Material and Google's internal `Wiz`. That makes it the authority even
though it is no longer the front door.

---

## 1. The foundations we are adopting

### 1.1 Motion

`md-sys-motion`. Durations in milliseconds, easing as cubic-bézier.

| Token | Value | Used for |
| --- | --- | --- |
| `short1`–`short4` | 50 / 100 / 150 / 200 | state layers, small fades |
| `medium1`–`medium4` | 250 / 300 / 350 / 400 | menus, dialogs, sheets |
| `long1`–`long4` | 450 / 500 / 550 / 600 | page transitions, ripples |
| `extra-long1`–`4` | 700 / 800 / 900 / 1000 | rarely; full-screen transitions |

| Easing | Curve | Meaning |
| --- | --- | --- |
| `emphasized` | `cubic-bezier(0.2, 0, 0, 1)` | the default for most motion |
| `emphasized-accelerate` | `cubic-bezier(0.3, 0, 0.8, 0.15)` | leaving an element |
| `emphasized-decelerate` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | arriving at an element |
| `standard` | `cubic-bezier(0.2, 0, 0, 1)` | small, in-place changes |
| `standard-accelerate` | `cubic-bezier(0.3, 0, 1, 1)` | |
| `standard-decelerate` | `cubic-bezier(0, 0, 0, 1)` | |
| `linear` | `cubic-bezier(0, 0, 1, 1)` | spinners only |

**Accelerate is for the way out, decelerate for the way in.** A dialog leaving gets
`emphasized-accelerate`; arriving gets `emphasized-decelerate`. This is the single
easiest thing to get backwards and it is why so much UI feels like it slams shut.

### 1.2 Shape

`md-sys-shape`.

| Token | Value | Applied to |
| --- | --- | --- |
| `corner-none` | 0 | nothing uses this |
| `corner-extra-small` | 4px | badges, small chips |
| `corner-small` | 8px | inputs, small cards |
| `corner-medium` | 12px | cards, dialogs |
| `corner-large` | 16px | sheets, large surfaces |
| `corner-extra-large` | 28px | bottom sheets |
| `corner-full` | 9999px | **every button**, chips, FABs |

Plus directional variants: `corner-large-top`, `corner-large-start`,
`corner-large-end`, `corner-extra-small-top`, and the matching bottom pair.

**Buttons are `corner-full`.** This is not a stylistic preference; it is the
token. A rounded rectangle button is a different component.

### 1.3 State layers

`md-sys-state`. A semi-transparent overlay of the *foreground* colour on the
element, at a fixed opacity per interaction.

| State | Opacity | Applies on |
| --- | --- | --- |
| hover | **0.08** | pointer over |
| focus | **0.12** | `:focus-visible` |
| pressed | **0.12** | `:active` |
| dragged | **0.16** | while dragging |

The layer colour is the element's own content colour — `on-primary` on a filled
button, `primary` on an outlined one. Not a grey, not the background.

This replaces every ad-hoc `hover:bg-muted/50` in the codebase. Those were not
subtle because grey is the wrong colour, they were subtle because `muted/50` over
white is about 3% of luminance. At 8% of `on-surface` it reads on any background.

### 1.4 Ripple

`ripple/internal/ripple.ts`. The "physics" is three constants:

| Constant | Value | Why |
| --- | --- | --- |
| `PRESS_GROW_MS` | **450** | the layer expands over 450ms — `long1` |
| `MINIMUM_PRESS_MS` | **225** | a layer that has been down for less than this **stays** that long. A 40ms tap still gets seen. |
| `TOUCH_DELAY_MS` | **150** | touch state is delayed 150ms so a scroll or a tap that turns into a scroll does not flash a press |

Bounded ripples are clipped to the element and grow from the pointer. Unbounded
ripples (icon buttons) are centred and sized to reach the far corner.

### 1.5 Elevation

`md-sys-elevation` is **tonal**, not a shadow scale. The tokens are
`level0`–`level5` = 0, 1, 3, 6, 8, 12 and they mean "how much this surface is
tinted toward the surface colour", not "how far above". Shadow is a secondary
signal on top of it.

We keep shadows — a CRM on a white page needs them to separate a menu from the
list behind it — but the token values are the source.

### 1.6 Type scale

`md-sys-typescale`. Size / line-height / tracking.

| Role | Size | Line height | Tracking |
| --- | --- | --- | --- |
| `display-large` … `display-small` | 57 → 36 | 64 → 44 | −0.25 → 0 |
| `headline-large` … `headline-small` | 32 → 24 | 40 → 32 | 0 → 0 |
| `title-large` | 22 | 28 | 0 |
| `title-medium` | 16 | 24 | 0.15px |
| `title-small` | 14 | 20 | 0.1px |
| `body-large` | 16 | 24 | 0.5px |
| `body-medium` | 14 | 20 | 0.25px |
| `body-small` | 12 | 16 | 0.4px |
| `label-large` | 14 | 20 | 0.1px |
| `label-medium` | 12 | 16 | 0.5px |
| `label-small` | 11 | 16 | 0.5px |

Title roles use the **brand** typeface; everything else uses plain. We have one
family, so we skip that distinction rather than fake it.

### 1.7 Colour roles

`md-sys-color`. ~50 roles, in families:

- **Primary** — `primary`, `on-primary`, `primary-container`, `on-primary-container`, `primary-fixed{,-dim}`, `on-primary-fixed{,-variant}`
- **Secondary / tertiary** — same shape
- **Neutral** — `surface`, `on-surface`, `surface-variant`, `on-surface-variant`,
  and five `surface-container` steps: `lowest`, `low`, ``, `high`, `highest`
- **Utility** — `error`, `outline`, `outline-variant`, `scrim`, `shadow`, `inverse-*`, `surface-tint`

Every colour in the system is one of these roles. A component never names a raw
colour. That is the rule that makes a dark theme a variable swap rather than an
audit.

## 2. Components — what we are adopting

### 2.1 Buttons (five variants, one token set)

`md-comp-{filled,outlined,text,elevated}-button`, `md-comp-icon-button`.

Shared across all four labelled variants:

| Property | Value |
| --- | --- |
| `container-height` | **40px** |
| `container-shape` | `corner-full` |
| `label-text` | `label-large` (14 / 20 / 0.1px) |
| `with-icon-icon-size` | **18px** |
| disabled container opacity | 0.12 |
| disabled label opacity | **0.38** |

| Variant | Container | Label | State layer | Hover elevation |
| --- | --- | --- | --- | --- |
| Filled | `primary` | `on-primary` | `on-primary` | `level1` |
| Elevated | `surface-container-low` | `primary` | `primary` | `level1` |
| Tonal | `secondary-container` | `on-secondary-container` | `on-secondary-container` | level0 |
| Outlined | transparent + `outline` | `primary` | `primary` | level0 |
| Text | transparent | `primary` | `primary` | level0 |
| Icon | transparent | — | `on-surface-variant` | level0 |

Icon button: 24px icon, 40px target when `touch-target` is applied.

**M3's disabled label is 0.38, not 0.5.** Ours was `opacity-50` on the whole
button, which dims the container and the label together and lands on the wrong
number for both.

### 2.2 Everything else we touch

Rather than restate all 95 component token files, the rules that change our
components:

- **Lists** — `md-comp-list`: one line is 56px (one-line), 72px (two-line). State
  layer on hover/press at the standard opacities.
- **Menus** — `md-comp-menu`: container `corner-extra-small` (4px) **top** for a
  menu opening downward, `surface-container`, width constrained, item height 48px.
- **Dialogs** — `md-comp-dialog`: `corner-extra-large` (28px), `surface-container-high`,
  enter `medium2` (300ms) `emphasized-decelerate`, exit `medium1` (250ms)
  `emphasized-accelerate`.
- **Navigation rail / drawer / bar** — active indicator is a **pill**, not a
  background change. That is the `md-comp-navigation-*` `active-indicator-*` token.
- **Text fields** — outlined variant: `corner-extra-small` 4px, `outline` border,
  56px container, floating label.
- **Chips** — assist/filter/input/suggestion: `corner-small` 8px, 32px container.
- **Scrim** — `scrim` at 0.32 for modal surfaces.

## 3. What we are not building, and why

Material 3 defines ~95 component token files. We are not implementing all of
them, and pretending otherwise would be a lie in a design doc.

Not adopted, because **the product does not have the component to restyle**:

FAB and its 14 size/tone variants · carousel · slider · switch · checkbox and
radio · linear and circular progress · search bar · date and time pickers ·
snackbar · banner · tooltip · bottom sheet · side sheet · chips (assist, input,
suggestion) · segmented button · tabs · badge · divider.

Not adopted, because **M3 has it and we have already solved it differently**:

- **Motion budget.** AGENTS.md already caps animation frequency by how often a
  thing is used. That is stricter than M3, which animates everything. We keep ours
  and take only the *values*.
- **Density.** M3 has a compact mode; we already have `--row-height` /
  `--control-height` behind `data-density`.
- **Dynamic colour.** M3 derives the palette from a seed colour at runtime via
  HCT. We use a fixed palette. Generating one at runtime is a real feature, not a
  restyle, and it is a separate piece of work.

## 4. Implementation plan

Ordered so each step is independently verifiable.

1. **Tokens.** `--m3-*` motion, shape, state, elevation, type-scale in
   `@theme`, plus the state-layer and ripple primitives.
2. **State layers everywhere.** One utility, applied to every interactive surface.
   This is the step that fixes the most.
3. **Ripple.** The three constants, bounded and unbounded.
4. **Buttons.** 40px, `corner-full`, `label-large`, 18px icons, real disabled
   opacities, state layers.
5. **Inputs.** 56px, 4px radius, state layer on the container.
6. **Lists, nav, menus, dialogs.** Shape + state layers + the motion tokens.
7. **Checks.** Every state is asserted in `tests/states.spec.ts`; the visual
   sweep is screenshot-reviewed at three widths.

### The one rule

**A state that is not visible is not a state.** Every layer in this document has
an assertion behind it, because the failure mode is silent: the class still
applies, the component still renders, nothing throws, and nobody can see it.
